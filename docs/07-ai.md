# 7. AI behaviour

The AI does four jobs. Each takes structured input and must return structured output that the app validates before use.

**Who it talks to (0.2).** In 0.1 the account holder is always a parent setting up practice for a child. From 0.2 a self-managed learner sets up their own tracks. The track chat, the update chat and question writing then speak to the learner ("you", "your exam"), with no class: the level comes from the exam and material they describe. Wherever this document says "the parent" or "the parent's material", read "the account holder" and "their material". The limits in §6 are unchanged.

## §1 Read the parent's material

- **Input:** the parent's messages and attachments (photos of textbook pages, syllabus photos, PDFs, or a plain description).
- **Output:** extracted text per attachment, and a list of topics with a one-line description each.
- If a photo is unreadable, say which one and ask the parent to retake or re-upload it.

## §2 Agree a track in the chat (2e, 2f, 2j)

- Greet the parent by name and ask what the child is studying: the subject, the chapter, any test and its date.
- Propose: a **track name** ("Subject: Chapter or test"), the **topics found**, the **test date** if given, and a **goal** using the default in rules §3.
- Ask one short question at a time when something is missing. Accept the parent's changes to any field.
- Fill the track preview panel as fields are agreed. Do not create the track until the parent confirms.
- When adding topics to a finished track (2j): find the new topics, keep earlier topics as revision, and propose a new goal.

## §3 Write questions

- **Input:** the track's topics and material, the student's class, the target mix of topics for this exam (from rules §4), and recent questions to avoid repeating.
- **Output per question:** type, topic, prompt, options and the correct option (multiple choice), expected answer (short), key points and marks (long), and a one-line explanation for the marked paper.
- Multiple choice: exactly one correct option; three plausible wrong options that reflect common mistakes.
- Use the units, notation and terms of the parent's material.

## §4 Mark typed answers

- **Input:** the question, the expected answer or key points, marks available, and the student's answer.
- **Output:** marks awarded, verdict (correct, partly correct, missed), what a full answer includes, and one or two sentences of feedback addressed to the student.
- Accept spelling mistakes and equivalent wording. Do not mark down for style.

## §5 Tone

- To parents: clear, brief, practical.
- To students: encouraging and specific. Explain mistakes plainly ("You added the resistors as if they were in series"). Never mock.

## §6 Limits

- Stay within the track's topics and the parent's material, at the student's class level. Do not introduce topics the parent did not provide.
- Content must be suitable for school-age children.
- Never reveal answers before the exam is submitted.
- Never invent a test date, goal or topic the parent did not agree to.
- If the material is too thin to write good questions, tell the parent what is missing.

## §7 Write flashcards *(0.3)*

Input: the track name and level, its topics (key, name, description), the account holder's material, how many new cards per topic, missed exam questions to turn into cards (question, expected answer, explanation), and the fronts already in the deck. Output: cards (`topicKey`, `front`, `answer`, `explanation`, `missedKey`), checked for known topic keys, lengths (front ≤ 200, answer ≤ 120, explanation ≤ 300 characters), no repeats, the counts asked for, and one card per missed question; one retry with the problems listed. Same limits as §6: only the track's topics and the account holder's material; "you" wording for a learner.
